# build has one codegen unit, which the shipped release build does not set.
#
# Who read it: a tool-assisted session, not a human reader. The
# aarch64-apple-darwin assembly of `compress`, `hmac_sha256`, `HmacSha256::new`,
# `Sha256::finalize`, `HmacSha256::finalize` and the HKDF was read branch by branch; the
# two Linux inventories were read item by item against the same classes, with the x86_64
# HKDF's two branches that are not preceded by their compare (`movzbl 7(%rsp)` before a
# `je`, `testb %dl, %dl` before a `je`) traced to their flags: the first `je` tests a copy
# count against 32 (`cmpq %rcx, %r13` two lines up, the load of the block counter `i` in
# between), the second tests `pos < out.len()` (`setb %dl`).
#
# The rule for every item: it may depend on a length (key, message, salt, input keying
# material, info or output), a loop counter, the SHA-256 buffer's fill count, the HKDF
# block counter `i`, the output position `pos`, or a constant; never on a key, message,
# state or derived byte. An `indexed` item is a load or store whose index register is one
# of those; the buffer it addresses may hold secrets.
#
# The source says the same of itself (`kdf/src/sha256.rs`: "Every branch and every index
# is on a length or a loop counter, never on message bytes"); this file records that the
# compiled code still has that property in this workspace's profile.
#
